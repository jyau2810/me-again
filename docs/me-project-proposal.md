版本：v1.0

## 1. 项目概述

《我》采用竖屏点触叙事与轻量环境交互。成年主角在日常现实和童年里世界之间往返：车灯有了阵营，学校在第四圈松开一道缝，临摹过的纸片朋友重新站起来，柜子收住雨声和呼吸，密林深处则留着一个从未成功的愿望。

故事不把现实写成等待被治好的问题，也不解释里世界的唯一真相。五章结束时，主角只是重新拥有几种很小、很具体的能力：认真看一眼、慢一点、承认喜欢、允许自己躲一下，以及在没有标准答案时继续往前。

## 2. 当前产品定位

| 项目 | 当前方案 |
| --- | --- |
| 游戏名 | 《我》 / Me Again |
| 类型 | 竖屏点触叙事、环境交互、低压力探索 |
| 内容范围 | 完整 5 章、30 幕、9 件收集物 |
| 核心交互 | 17 类点击、重复、拖放、轨迹、描线、长按和多点触控 |
| 战斗与压力 | 无战斗、无死亡、无倒计时、无惩罚性失败 |
| 叙事气质 | 克制、温柔、半自传虚构；结尾明亮，里世界真相开放 |
| 当前引擎 | Godot 4.7.1 / GL Compatibility |
| 当前平台 | 本地桌面制作与试玩；Web/桌面导出待外测后确定 |
| 团队假设 | 个人开发，AI 辅助原创美术，外部 CC0 音频 |

游戏总时长和最终发行定价不在当前阶段预设，先由 5–8 人外部试玩验证实际节奏与阅读密度。

## 3. 目标玩家

- 喜欢叙事解谜、环境叙事、轻量探索和情绪向独立游戏的玩家。
- 对童年幻想、校园记忆、成长后的感受力变化有共鸣的成年人。
- 能接受慢节奏、无战斗、没有标准答案的体验者。

第一轮测试优先邀请没有读过母本、没有参与制作的人，避免开发者知识掩盖提示问题。

## 4. 设计支柱

### 世界在重复动作中改变

重复观察车窗、绕学校走四圈、反复开合柜门都不是进度条。每次动作都应改变光、声音、空间或物件状态，让入界发生在玩家手里。

### 童年幻想成为环境规则

车灯的眼睛、粉笔留下的慢路、分镜的情绪顺序、声音能躲藏的位置和两只手影的合作，都从主角小时候看世界的方式中长出。

### 反馈来自场景

可操作物直接留在背景与物件层中，不用“观察”“前往”“执行”式按钮代替动作。普通点击通过图文观察卡回收，完成一幕通过图文回忆卡收束；提示优先使用光影、轻动、声音和环境短句。

### 变化落回现实

收集物不增加能力。它们回到桌角、书页和房间里，成为主角重新允许自己喜欢、停下或联系他人的痕迹。

## 5. 五章内容

| 章节 | 主题句 | 入界与核心玩法 | 现实回声 |
| --- | --- | --- | --- |
| 灰色早晨 | 我已经多久没有认真看世界了？ | 观察车窗、辨认车辆阵营、后座路线、信号节奏 | 通勤时没有立刻低头 |
| 绕完这一圈 | 跑着跑着，世界好像在变…… | 环绕学校、第四圈慢行、粉笔线索、旧课桌路径 | 为粉笔和星星留出桌角 |
| 纸片朋友 | 那时候以为，他们会永远陪着我。 | 宽容描线、原创纸片朋友、情绪分镜、书签补桥 | 买一本真正想看的新漫画 |
| 柜子里的呼吸 | 那个让我安心的角落去哪了？ | 柜门开合、声音摆放、空间比较、长按呼吸 | 调暗灯，关掉不急的提醒 |
| 密林之后 | 前面还有啥呢？ | 树影探索、旧意象汇合、化石遇见、双指合作 | 整理桌面，联系很久没问候的人 |

每章六幕，依次经历现实开场、渐进入界、里世界交互和现实回声。完整场景链见 [游戏脚本索引](./game-script-index.md)。

## 6. 交互与界面方案

### 场景原位交互

- 点击热区贴合闹钟、钥匙、车窗、车辆、粉笔痕、漫画页、柜门、树影等画面物件。
- 拖动和轨迹发生在座椅缝、跑道、桌面划痕、纸片舞台等场景空间中。
- 图标仅在声音摆放等无法直接具象的交互里使用，并保持为场景中的纸片或声纹，而不是工具栏按钮。
- 双指动作提供鼠标/键盘替代，不因设备输入方式阻断流程。

### 反馈层级

1. 物件轻动、声音、亮度或局部状态变化。
2. 带物件局部图的观察卡和一句短文本。
3. 卡住后由场景元素给出渐进提示。
4. 一幕结束出现图文回忆卡，再进入下一幕。

背景持续可见，交互面板不得用大面积纯色遮挡场景。全局按钮只服务标题、章节选择、收集册、制作信息和必要导航，不承载场景动作。

### 文本原则

- 成年现实短、硬、克制；入界允许“不确定”和“好像”。
- 儿童痕迹短、直白、具体，不总结人生。
- 目标与提示写成环境线索，不写问卷、产品说明或操作手册。
- 完成卡提供画面与余韵，不替玩家宣布一个标准感受。

## 7. Godot 技术方案

| 模块 | 当前实现 |
| --- | --- |
| 引擎与渲染 | Godot `4.7.1.stable.official.a13da4feb`，GL Compatibility |
| 分辨率 | 720 × 1280 逻辑画布；桌面 540 × 960 并最大化 |
| 内容目录 | 5 章、30 幕、9 收集物的静态 catalog |
| 交互系统 | 17 类语义契约，统一完成事件和指标 |
| 跨章状态 | 六字段白名单、连续章节解锁、收集与回声 |
| 续玩 | 独立 session 存档恢复精确场景和静音设置 |
| 存档安全 | 版本化 JSON、临时文件写入、备份恢复、损坏净化 |
| 音频 | Music / Ambience / SFX 三类播放与场景切换 |
| 试玩记录 | 本地 NDJSON，记录耗时、错误、提示与交互指标，不记录个人信息 |

旧 `legacy-web-cocos-prototype/` 仅保留为历史实验。当前工程不从旧 Cocos 代码续建，也不以小游戏构建作为引擎选择前提。

## 8. 美术、物件与音频

### 当前资产

- 7 张竖屏背景/主视觉：标题、五章主背景和现实回声背景；公交车窗与操场跑道版本已经重新生成并替换。
- 4 张透明交互物件图集：日常物件、动作物件、纸片物件、柜子/森林物件。
- 30 条 CC0 音频：章节音乐、环境声和交互音效。
- Noto Sans CJK SC：随工程打包并保存许可证。

### 视觉原则

- 现实低饱和、留白更多；里世界用旧纸、石墨、粉笔和薄彩增加可感知变化。
- 背景图不烘焙 UI、可读文字、商标或真实 IP。
- 第三章纸片朋友为原创的童年临摹感形象，不复刻现实漫画角色。
- 交互物件需要与背景共享线条、纸张颗粒和色彩，不呈现通用 App 图标质感。

生成提示词和文件映射见 [生成美术记录](./generated-art-assets.md)；音频逐条来源见 [音频许可证清单](./audio-licenses.md)。

## 9. 当前验证结果

- 状态与存档：138 条自动断言通过。
- 内容目录：5 章、30 幕、9 件收集物自检通过。
- 交互系统：158 条自动断言、17 类契约自检通过。
- Godot 资源导入和主场景 headless smoke test 通过。

自动验证证明结构、状态链和交互契约一致，但不能代替玩家对热区、图文反馈、节奏和情绪的判断。

## 10. 平台与发布路线

1. 当前先用 Godot 本地版完成 5–8 人外部试玩。
2. 根据试玩设备、传播需求和技术风险，选择 Web/itch.io 或桌面包作为首个导出目标。
3. 安装与 Godot 4.7.1 精确匹配的 export templates，建立并验证 export preset。
4. 微信/抖音小游戏作为独立平台课题重新评估，不沿用旧 Cocos 方案；需要另验导出、包体、SDK、音频、触控和合规。

本机当前缺少精确匹配的 export templates，因此尚未产出发布包。

## 11. 风险与应对

| 风险 | 影响 | 当前应对 |
| --- | --- | --- |
| 场景热点不明显 | 玩家寻找按钮或无目的点击 | 使用物件轻动、局部明暗、声音和观察卡；外测记录误点区域 |
| 图文卡过于频繁 | 打断画面与节奏 | 每次只保留一条短反馈，完成卡与普通观察卡分级 |
| 背景与热点不一致 | 玩家无法把动作映射到物件 | 使用 4 张透明物件图集贴合场景；公交和跑道背景已纠正 |
| 17 类交互学习成本高 | 后章操作难以理解 | 复用动作语法、宽容判定、多点触控提供替代输入 |
| 文本过度解释 | 情绪变成结论或说教 | 以母本为基线，运行时文本改写为场景线索和短反馈 |
| AI 美术风格漂移 | 画面像素材拼贴 | 固定旧纸/石墨/薄彩语言，保存提示词并统一二次整理 |
| 外部素材授权不清 | 无法发布 | 只接入可追溯 CC0 音频和已保存许可证的字体 |
| 缺少 export templates | 无法产出发布包 | 外测与制作继续使用本地版，阶段 8 安装精确版本模板 |
| 小游戏路线不确定 | 平台适配成本失控 | 单独立项评估，不让平台假设反向限制当前 Godot 架构 |

## 12. 当前验收与下一步

当前制作整合的验收边界：五章可在 Godot 本地连续运行；场景原位交互、图文观察卡、完成回忆卡、音频、存档、续玩和收集链路可用；三组自动自检全部通过。

下一步进入 5–8 人外部试玩，重点记录：

- 玩家是否自然点击场景，而不是寻找操作按钮。
- 图文观察卡是否足够明确，完成回忆卡是否保留余韵。
- 公交、跑道、柜子、树林等背景空间是否清楚。
- 哪些幕出现误点、拖动失败、长按过久或多点触控困难。
- 五章连续游玩时的文案密度、声音切换、存档恢复和整体节奏。

完成试玩修复与回归后，再进入导出和发布准备。
