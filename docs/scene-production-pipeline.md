# 《我》单幕资产生产与验收流程

版本：v0.1

日期：2026-08-07

## 1. 适用原则

每次只推进一个可验收场景。当前样板为 `c01_s02_commute_window`；在它完成视觉方向、分层资产、场景合成、人工校正和交互验收之前，不批量生产其他场景。

母本和游戏脚本决定叙事目标，场景资产清单决定生产边界，Godot 合成结果决定最终视觉验收。单张生成图好看但无法拆层、无法交互或无法稳定落位，不算可用资产。

## 2. 八道生产门

### Gate 1：场景意图

产物包括情绪句、玩家目标、进入状态、退出状态和本幕必须出现的叙事对象。

通过条件：只看场景说明即可判断这一幕为什么存在，以及玩家完成后发生了什么变化。

### Gate 2：视觉方向

围绕同一叙事框架制作三个方向稿，只比较线条、颜色、光线、人物处理和材质；此时画面布局只是方向评审载体，不视为最终构图。

通过条件：明确选定一个方向，并记录保留点、修改点和禁止点。未选中的方向不进入正式生产。

### Gate 3：构图灰稿

在选定视觉方向后，用简单形状重新确认视角、人物位置、视线、交互区、字幕安全区和主要遮挡。

通过条件：不依赖美术细节也能读懂空间和操作对象；不存在需要靠 UI 补救的构图问题，并由方向评审人确认后才进入分层资产。

### Gate 4：分层资产

按清单分别生产背景、人物、物件、状态图和光效。每项资产先单独检查，再进入合成。

通过条件：资产可独立替换，透明边缘干净，同组状态画布和锚点一致，未把交互物永久画进背景。

### Gate 5：场景合成

在固定 720 × 1280 逻辑画布中合成背景、人物、物件和光效，输出静态预览与关键状态预览。

通过条件：透视、比例、光向、遮挡、色彩和信息密度统一；关键交互物在实际显示尺寸下可读。

### Gate 6：人工落位校正

在 Godot 校正工具中拖动目标，分别调整视觉矩形与命中矩形，设置层级和显示模式，然后保存仓库内 JSON。

通过条件：重新打开工具后可恢复布局；运行时读取同一布局；校正不需要修改 GDScript 常量。

### Gate 7：交互接入

按脚本接入点击、拖放、状态变化、人物动作、局部反馈和音频，不新增说明式按钮。

通过条件：玩家能从场景变化理解下一步；失败只轻退回；画面反馈先于文字反馈。

### Gate 8：单幕验收

在桌面窗口和移动端等比视图检查画面、触控、状态、字幕、音频与恢复流程。

通过条件：该幕视觉与交互问题已关闭，相关脚本、清单、布局和资产状态同步更新，才允许复制流程到下一幕。

## 3. 资产状态

- `planned`：清单已定义，尚未生产。
- `candidate`：已有候选图，等待单项确认。
- `approved`：单项效果、规格与原创边界通过。
- `composited`：已进入场景合成并通过整体检查。
- `integrated`：已接入 Godot 与交互状态。
- `rejected`：不再使用，保留拒绝原因但不进入运行时目录。

任何资产不得从 `candidate` 直接跳到 `integrated`。

```text
    c01_s02_commute_window/

      characters/
      props/
      effects/

game/data/scene_layouts/

```

方向稿与生产资产分开。未确认的候选图不放入 `production/`，运行时也不引用 `style-studies/`。

## 5. 命名与版本

- 背景：`bg_<scene>_<state>_vNNN.png`
- 人物：`char_<identity>_<pose>_<state>_vNNN.png`
- 物件：`prop_<object>_<state>_vNNN.png`
- 光效：`fx_<scene>_<effect>_<state>_vNNN.png`
- 合成预览：`preview_<scene>_<state>_vNNN.png`

新候选使用递增版本号，不覆盖已确认文件。替换运行时资产时，先更新清单状态与引用，再删除已明确废弃且可从 Git 恢复的旧候选。

## 6. 布局数据职责

每个目标分别记录：

- `anchor`：在 720 × 1280 画布中的归一化中心点。
- `visual_size`：独立物件或人物的显示尺寸；背景区域可为空。
- `hit_size`：点击或拖放命中尺寸。
- `z_index`：合成层级。
- `mode`：`sprite`、`region` 或后续扩展模式。
- `asset_path`：独立视觉资产路径；纯背景区域为空。
- `locked`：确认后可锁定，避免误拖。

运行时优先读取 `game/data/scene_layouts/<scene_id>.json`。未迁移场景继续使用 `interaction_scene_layouts.gd` 的旧数据回退，直到逐幕完成迁移。

## 7. 人工校正操作

1. 在 Godot 编辑器中打开 `game/scenes/tools/scene_layout_calibrator.tscn`。
2. 运行当前场景，左侧画布显示背景、资产和热区，右侧列表显示所有目标。
3. 点击目标或列表项选中；拖动调整中心点。
4. 使用尺寸控制分别调整视觉尺寸和命中尺寸，使用层级控制调整遮挡。
5. `region` 目标只显示校正框，不渲染重复物件；`sprite` 目标显示实际资产。
6. 点击保存，将布局写回 `res://data/scene_layouts/`。
7. 重新加载并运行正式场景，确认运行时与工具一致。

## 8. 每轮评审输出

每次需要用户判断时，只提交当前 Gate 所需材料：

- 方向评审：三张同构图方向稿和差异说明。
- 单项资产评审：单个背景、人物或物件及其规格，不混入其他未确认资产。
- 合成评审：静态合成、关键状态对比和待校正清单。
- 交互评审：可运行场景、状态路径和已知限制。

这样可以明确问题属于方向、单项资产、合成落位还是交互，不把多个阶段的问题混在一次返工中。
